API

Everything on this site comes from these JSON endpoints. No key needed, CORS is open, and responses are cached for 60 seconds. {net} is mainnet or testnet. Amounts are in duffs (1 DASH = 100,000,000 duffs); times are unix seconds.

GET /api/v1/status

Our dashd's sync state, the crawler's state and the payment index range, per network.

GET /api/v1/{net}/summary

The latest finished crawl, the crawl about 24 hours before it, every distribution from the latest crawl (dists[scope][dim] = [[key, count], …], largest first) and networks: per address network (ipv4, ipv6, onion, i2p, cjdns, always in that order), {network, known, tried, reachable, masternodes, crawled, reason}. known counts addresses heard of in the past week; a network we have no route to is crawled: false with a reason, and its addresses never count as unreachable.

Scopes: all (every node that answered), nonmn (those that aren't masternodes), mn and evo (every enabled masternode or evonode, reachable or not, keyed by the user agent it last announced in the past 7 days, else Unknown).

Dimensions: ua, version, client, protocol, country (ISO 3166), asn, network, reachable, status and type (masternode scopes).

curl https://nodes.dashhq.org/api/v1/mainnet/summary | jq '.dists.mn.version'

GET /api/v1/{net}/history?scope=mn&dim=version&days=30&top=8

A time series of one distribution: {resolution, t: [...], series: [{key, values}]}. Up to 14 days back it has one point per crawl; past that, daily averages. Keys outside the top top (by total over the window) fold into Other. dim=totals returns reachable nodes, enabled masternodes and reachable masternodes instead. days is one of 1, 7, 14, 30, 90 and 365 (default 30); top is 1 to 20 (default 8).

GET /api/v1/{net}/geo

Every node that answered the latest crawl, counted per city and never by address: {crawl_id, points: [{lat, lon, city, country, nodes, masternodes}], unlocated}. Onion and I2P nodes have no location and only count in unlocated.

GET /api/v1/{net}/masternodes

Every registered masternode with its latest port check (reachable is null when the latest crawl didn't check it), announced user agent, geolocation and 7- and 30-day port-check uptime. Geolocation is country (ISO 3166), continent (two-letter code), city, city-level lat/lon, asn and as_org; network is the service address's network. The map page is drawn from this endpoint.

GET /api/v1/{net}/masternodes/{protx}

One masternode: everything from the list plus collateral and keys, every registered Core address (core_p2p: [{address, network}]), version history, 90 days of daily uptime and its 25 latest payments.

GET /api/v1/{net}/masternodes/{protx}/payments?before={height}&limit=100

Older payments, newest first. Page with before set to the last height you got.

How the data is collected

Every 15 minutes the crawler opens a P2P connection to every registered masternode's Core address, to every node that answered in the past week, and to new addresses learned from our dashd and from other nodes' getaddr replies (in addrv2, so including Tor, I2P and CJDNS addresses). Onion peers are reached through Tor, I2P peers through I2P and CJDNS peers through a cjdns node; IPv6 only when our host has an IPv6 route. It completes the version handshake and disconnects. It announces itself as /dash-nodes:…(nodes.dashhq.org)/, doesn't relay transactions and keeps nothing but what the node announces. Masternode registration data and payments come from our own dashd. Reachability is measured from one vantage point, so a node that blocks or rate-limits us shows as unreachable even when others can reach it.

Non-masternode IP addresses are never published, only counted.

This site and API are served by Cloudflare from documents the crawler publishes after each crawl, so they stay up when the crawler doesn't; the header says when the last crawl finished.
